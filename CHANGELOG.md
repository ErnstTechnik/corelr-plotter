## [1.0.0] - 2026-10-31
The first release. Everything below was written during the development that led to it.
### Fixed
- **The IDE export failed on CMake 3.x** (`cmake/ExportIno.cmake`, found by the first run of the `release` workflow on GitHub, 2026-10-31): in a script run by `cmake -P` the empty linker-flag field of `size_flags.txt` was dropped from the list (policy CMP0007 not set), and the status field vanished with it. The line is now read with a regular expression, whatever the policy; the exported sketches are byte-identical to before.
- **The 28BYJ-48's real gear ratio** (`HwConfig.h`): `MOTION_STEPS_PER_REV` 2048 was the "64:1" of the data sheets; the gear train is 63.68395:1, so the shaft needs **2037.886 steps a turn** (`MOTION_STEPS_PER_REV_X1000` 2037886). A step winds 53.96 um of cable, not 53.69: every length was 0.5 % short (the pen went farther than commanded, and at the top limit the margin of 50 mm shrank to 33 mm with 1.5x the tension). Same flash and RAM. **Recalibration: the stored step counts are stale, confirm *Calibrate machine* once after flashing** (MAJOR at release). Host-verified only.
### Changed
- **The serial image no longer carries dead SD code: 28 852 -> 28 766 bytes of flash (1 954 free), RAM unchanged** (936). **A module or a library that an image does not use is no longer compiled in it** (`cmake/variant_modules.txt`, one list read by the build, the IDE export, the reference build and the documentation; `tests/tools/test_variant_modules.py` checks it against the guards): serial no longer builds `SDReader`, sdfat and SPI (-2 B more: sdfat's empty constructor stub), sd no longer builds `Uart` and `SerialLink`. Both images identical to the Arduino IDE's reference build (`compare_with_ide.sh`) and the exported sketches build to the same images. `SDReader.h`/`.cpp`, `Uart.h`/`.c` and `SerialLink.h`/`.c` are now wholly under `#if CORELR_JOB_SOURCE == ...` (only `SDReader.cpp`'s pin checks were), so a module that belongs to one image is empty in the other; the serial image used to compile `SDReader.cpp` and keep an `SdFile` constructor and `Print::write` (84 B). Found by making the headers conditional for the documentation. SD image byte-identical (`e9b77dcb`). Same behaviour, host-verified only (`test_sdreader`, `test_seriallink`, `test_uart`, the bring-up sketches build), **not flashed**.
- **CI and release use Doxygen 1.15.0** (the composite action `.github/actions/doxygen`: the project's release binary, checked against its published SHA-256) instead of Ubuntu 22.04's 1.9.1, which gave some 2 400 markup warnings on the requirement links, the protocol labels and `\r\n` in code spans (CI run of 2026-10-31). Making the documentation build cleanly with 1.9.1 too is the fallback if the binary does not run on the runner.
